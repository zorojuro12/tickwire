  first, and the user corrected it. `docs/dev-workflow-guide.md` §2 says the
  architectural layer ran once (the architecture-resolution doc) and a phase

- **Rewind samples the server's 20 Hz snapshot history via a shared
  `net::samplePlayerAt`, not per-tick authoritative positions.** See the plan's
  Self-Review. This is a departure from Valve's reference design, and it was
  argued deliberately.
- **`kMaxRewindTicks = 45` is derived** from the server's 16-snapshot
  `history_` depth. The derivation is in plan Task 4.
- **Folded into P6:** the id-reuse ghost-hit rule (plan Task 4 CP3) and P3's
  open "`hits_` never reset on id reuse" note (Task 5 CP3). Session tokens were
  **deliberately excluded**, and history says so.

## What Worked
- **Probed GCC 10 in the pinned image** before writing Task 1's contract.
  `S{.a=1, .b=2, .c=true}` with a trailing `uint32_t d;` fails with
  `-Werror=missing-field-initializers`. `uint32_t d = 0;` compiles clean and stays
  aggregate and trivially copyable. This is why the plan declares
  `view_tick = 0`.
