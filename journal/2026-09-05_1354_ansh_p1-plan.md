## Decisions Made

Six calls that neither spec doc had settled. Reasoning for each is written into
the plan itself (Global Constraints, or the relevant task preamble) rather than
duplicated here — these are one-line pointers.

- **Little-endian, explicitly encoded**, magic `0x52495754` (LE bytes spell `TWIR` in a hexdump) — plan § Global Constraints.
- **New `libnet` STATIC target on top of `libsim`, linked `PUBLIC`** — inherits the pinned float flags by the same build-graph mechanism P0 established, rather than by a second copy of the flag list.
- **The POD payload types (`PlayerState`, `InputCommand`, `WorldSnapshot`) land in `libsim` at P1, not P2.** The wire format can't be called frozen over types that don't exist. `World` and all behavior still stay in P2, so `libsim`'s 100% coverage floor is untouched — constants and structs add no executable lines.
- **`loss_permille` as an integer, and no `std::uniform_*_distribution` anywhere.** Distribution objects aren't specified to reproduce the same sequence across implementations, which would silently break the determinism claim `SimulatedTransport` exists to make. Plan § Task 6.
- **`SimulatedTransport` delays on receive, not send** — each end delays its own inbound traffic, so a two-ended test yields an RTT equal to the sum, which is what a slider labelled RTT means.
- **`recvmmsg`/`sendmmsg` deferred to P5.** They're batch calls; `tryReceive(PacketSlot&)` hands back one packet at a time by design. Batching belongs with P5's receiver thread, where it's measurable.

Also reserved-but-not-implemented at P1, following the resolution doc's
precedent for clock sync: `seq`/`ack_seq` header fields for the join/leave
reliability channel, whose logic needs a session concept and therefore waits
for P2.

## What Worked

- **Hand-computing the golden byte vectors while writing the plan**, rather than leaving them for execution to fill in. Forced the layout to be fully decided (24-byte header, 17-byte `InputCommand`, `8 + count × 24` snapshot) and surfaced the MTU arithmetic as a `static_assert` the plan can name: `24 + 8 + 32 × 24 = 800 ≤ 1200`.
- **Working each checkpoint's RED case through by hand before committing to it.** This is what caught the problem below, and it caught it three times.

## What Didn't Work

- **Writing "reject the malformed case" as its own checkpoint, three separate times** — short-buffer header rejection, `InputCommand` framing, and the MTU-send guard. Each looked like a real RED→GREEN cycle and each was already satisfied by an earlier checkpoint's contract (`ByteReader`'s sticky `ok()`, the `remaining() == kInputBytes` entry guard, the `payload.size() > kMaxPacket` guard). The `writing-plans` skill warns about exactly this — a checkpoint whose test passes when written contradicts its own "expect FAIL" template and can lead a cold executor to "fix" a correct test until it fails. Their assertions were folded into the checkpoints that establish them.

  Worse, the first two times I *noticed* mid-checkpoint and wrote the correction into the plan as an inline "Expected: PASS — fold this into Checkpoint 1" note, leaving a fake checkpoint in the document for an executor to trip over. Recording the fix isn't the same as making it — the same lesson the previous session logged about `CLAUDE.md`, in a new place. Both were then properly deleted and renumbered.

- **A first draft of `decodeSnapshot`'s guards that clamped `count` to `kMaxPlayers` instead of rejecting.** Clamping is memory-safe at that line but leaves `out.count` describing more players than were filled — the same out-of-bounds read one level up, in the caller. Changed to a rejection, and the plan says why so P2 doesn't reintroduce it.

## Open Questions / Blockers

- **Does the container have a working loopback interface?** Task 5 (`UdpTransport`) is the only task that needs one. Unverified — I chose not to spend a container round-trip on it while writing the plan. The task ordering makes a failure a detour rather than a stop (Tasks 1–4 and 6–8 stay executable), and the plan says to record it in `docs/project-history.md` rather than work around it silently, since a container networking constraint would also constrain P2's demo.
- **`std::bit_cast` is assumed unavailable in GCC 10's libstdc++** (added in GCC 11). Not measured. The plan sidesteps the question by mandating `std::memcpy` punning, which is well-defined either way — so this is a non-blocking uncertainty, deliberately not turned into a verification task.
